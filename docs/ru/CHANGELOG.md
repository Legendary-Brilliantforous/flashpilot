## 1.3.2 (бейдж называет USB-протокол)

- Бейдж режима больше не показывает OTHER для подключённого устройства:
  «MEDIATEK» не содержит подстроку «MTK», поэтому общий ярлык режима MTK
  («MEDIATEK MODE (VID 0x0E8D PID 0x2008)») проваливался в OTHER.
- Телефон MediaTek/Tecno в обычной загрузке с неподходящим PID (0e8d:2008,
  интерфейс still-image/MTP, без строки ADB) больше не считается MediaTek
  низкого уровня: только прошивочные PID (BROM/preloader/DA) получают ярлык
  низкого уровня, остальное проходит к именованию по интерфейсу
  (ADB/MTP/PTP/DIAG/storage/RNDIS) во ВСЕХ списках устройств — раньше
  протокольное сканирование выполнялось только для Samsung.
- Транспорты Rust: неподходящий PID, всё ещё экспонирующий интерфейс
  still-image (класс 6), сообщает MTP вместо USB; железо без интерфейса MTP
  сохраняет честный ярлык USB.
- Метка подключения показывает «MediaTek device (normal boot)» вместо
  «MediaTek low-level» для непрошивочных PID.
- Qualcomm EDL сохраняет свой чип бейджа: «EDL MODE (Qualcomm Emergency
  Download)» содержит подстроку «download» и раньше проваливался в чип DOWNLOAD.
- Qualcomm HS-USB Diagnostics (05c6:9006, например Moto в режиме Diag)
  называется «QUALCOMM DIAG MODE (HS-USB Diagnostics 9006)», а не сворачивается
  в общий ярлык «QUALCOMM DEVICE».

## 1.3.1 (исправление ModeBadge)

- Бейдж режима устройства (верхняя панель, у Stop) следует за ВЫБРАННЫМ
  устройством и больше не читает MTP для конфигураций Qualcomm-normal
  (подстрока «normal» проваливалась в чип MTP).

## 1.3.0 (классификация устройств + выбор)

- Несовпадающие устройства (композиты производителя/diag) сообщают «USB»
  вместо ошибочного ярлыка «MTP».
- Когда USB-выбор промахивается на флапе, инструменты ADB показывают выбор
  daemon-row вместо отказа: выберите, какое устройство является целью операции.

## 1.2.9 (идентичность отображаемого устройства)

- Переключение устройств больше не откатывается к первому телефону: 3-секундное
  обновление, разрешитель live-identity и все откаты опираются на отображаемое
  устройство; путь отсутствия сохраняет статические плитки строки.

## 1.2.8 (исправление переключения списка устройств)

- Перестроение строки подключения повторяет попытку, когда второй скан роняет
  устройство, только что увиденное монитором (окно повторного перечисления):
  оба устройства отрисовываются и переключение работает на флапающих каналах.

## 1.2.7 (привязка идентичности цели)

- Устройство, заменившее другое и занявшее повторно использованный bus:addr,
  отклоняется (проверка zero-touch serial на цели; открытие совпадает по
  vid/pid/bus/addr, а не по serial). Закрывает сценарий замены устройства:
  транспорт никогда не следует за другим устройством.

## 1.2.6 (откат на daemon-row)

- Инструменты ADB откатываются к строке daemon ADB, когда выбор сканом USB
  промахивается на флапающей шине (демон работает по TCP и остаётся
  авторитетным для присутствия). Исправляет «показывает подключено, но actions
  говорят no adb».

## 1.2.5 (оверлей ADB в углу MTK)

- Ветка угла mtk_devs теперь показывает оверлей ADB как sibling-ветки: телефон
  Tecno/MTK с авторизованным ADB называет транспорт в правом верхнем углу
  (раньше показывалось только «MediaTek low-level», а ADB Status показывал
  connected).

## 1.2.4 (исправление ADB AUTH)

- Чередование хешей AUTH исправлено: SHA-256 остаётся в игре между раундами
  токенов (нечётные раунды SHA-256, чётные SHA-1). Раньше потерянная подпись
  раунда 1 на шумном канале пере-токенилась в стену SHA-1 → ложное
  «not authorized», пока устройство было авторизовано.
- `_wait_for_adb` терпит транзитные сбои сканирования в ходе ожидания.

## 1.2.3 (устойчивость выбора)

- Выбор устройства с settle-retry: каждый запуск инструмента повторяет попытку
  один раз через 2,5 с, когда сканирование транзитно промахивается по
  пере-перечисляемому устройству, вместо отказа «no device», пока GUI показывает
  его подключённым. Chooser, отменённый пользователем, никогда не повторяется.

## 1.2.2 (безопасный для модема ADB + исправления отображения)

### Транспорт ADB (исправлено)
- Пути poll/monitor/display теперь zero-touch (`adb-devices --no-probe`,
  `adb_presence`): никаких open/claim/handshake из циклов. Исправляет
  пере-перечисление USB-модемов каждый цикл (проверено живьём: 114 тихих циклов
  опроса на MSM8916-модеме после штормов ~1 Гц).
- Лесенка делегирования при борьбе за claim: нативный → Rust server transport
  (`adb-shell-server`, только явный serial) → host-бинарник → спасательный
  kill (крайняя мера). Операции ADB теперь успешны при удержании интерфейса
  системным сервером вместо его вытеснения.
- Исправление слияния USB-ADB: строки строк анализируются (структурная
  десериализация молча давала нулевое количество записей ADB, поэтому строки
  никогда не несли состояние ADB).
- Угол QCOM теперь показывает оверлей ADB как sibling-ветки.

### Надёжность (исправлено)
- Единый settle-retry при транзитных отказах шлюза (окна пере-перечисления)
  с понятными сообщениями; `rescue=False` + закрепление serial во всех
  диагностических/инструментальных shell; обнаружение Firehose FAIL;
  паники ввода CLI; зажимы аллокации; гарды обхода tar; строгая XML-нумерика.

## 1.2.1 (Стабильный релиз)

### Поддержка нескольких устройств (новое)
- Подключите несколько телефонов: строка подключения перечисляет каждый
  (модель · серийный · транспорты); клик по строке покажет его.
- Каждая операция спрашивает, к какому телефону применяется, если совпадает
  несколько (молча при 0–1 совпадении). Строки консоли несут тег `[device-key]`.
- Одна операция на устройство: разные телефоны могут прошиваться параллельно;
  один и тот же телефон всё ещё сериализуется. Глобальный STOP вещает всем
  runner'ам.
- Стабильная идентичность (`python/core/devices.py`): `adb:<serial>` →
  `usb:<port-path>` → неустойчивый откат. Цели пере-разрешаются перед открытием
  сессий, поэтому пере-перечисление USB больше не осиротевает прошивку
  (`usb device Fail`).
- Список только телефонов: хабы, HID, веб-камеры и кардридеры отфильтрованы.
- Новый транспортный режим `SPD` + потоки только для чтения определения
  Qualcomm/SPD.

### Per-chip EXPERIMENTAL (новое)
- Samsung `Knox / Warranty`, Qualcomm `QCN / Modem`, per-chip `IMEI Repair /
  Change`, `eMMC / UFS` — янтарные сворачиваемые панели на странице чипа-
  владельца (без глобальной страницы LAB). Чекбокс владения при каждом запуске;
  изменение IMEI дополнительно требует ввода `I UNDERSTAND`. Аудит-лог;
  сохранённые подтверждения никогда не проходят автоматически
  (`check_gate_strict`).

### MTK BROM (исправлено + улучшено)
- **PID/стадии скорректированы** по конвенции mtkclient (`0e8d:0003`=BROM,
  `0e8d:2000`=preloader) в Rust, Python, GUI-ярлыках, логах и документации.
- Новая команда моста `mtk_crash_brom` + поток `MTK crash preloader into BROM`
  (зарегистрирован под MTK BROM).
- `_wait_mtk_brom_target()` предпочитает стабильный удержанный BROM окну
  preloader; обнаружение DA отказывает урезанным (<1KB) бинарникам.

### Odin / прошивка (закалено)
- `_prepare_download_session()`: отключение kernel-драйвера + 3× повтор
  рукопожатия через пере-перечисление; принимаются все PID Odin; кэш PIT
  прогревается до прошивки.
- odin4 закреплён через `-d /dev/bus/usb/BBB/AAA` + одна автоматическая повторная
  попытка при потере USB; трейлер `.tar.md5` заякорен к концу файла (потоковый,
  без полного чтения в RAM).
- Нативная smart flash логирует MB/s + ETA по каждому разделу.

### Закалка надёжности (по отзывам)
- Sahara: HELLO command/version/mode/packet-size валидируются при разборе
  (раньше любой блоб ≥32 байт доверялся); самопроверка формата передачи теперь
  round-trips structs вместо потери байт; сбои закрытия логируются; отключение
  выполняется до claim; рукопожатие сообщает transfer/close/reset исходы в JSON
  вместо их отбрасывания (reset явный и видимый).
- ADB auth: ограниченный экспоненциальный backoff между раундами токенов;
  одноразовая пауза генерации ключа анонсируется вместо вида зависания.
- MTK: настроенный размер пакета реально доходит до сессии DA (раньше
  вычислялся и терялся; сессии жёстко 64K), зажат 512B–1MB.
- Safety-бэкапы: при сбое печатают непропускаемый баннер с затраченным временем
  и подсказкой STOP (контракт неизменен: никогда не блокирует операцию).
- Экспериментальные шлюзы: iCloud + Pixel-потоки перенесены на строгие ack на
  каждый запуск; токены ack GUI теперь считаются по фичам с истечением
  (без перетекания между фичами, без потерянных ack, без устаревших
  авторизаций).

### Исправления GUI
- Красные границы верхней панели + усадка кнопок прослежены к одновременным
  анимациям shake/rubber и акцентно-окрашенным кольцам фокуса: анимации
  сериализованы через `_anim_lock` + полная очистка; новые нейтральные токены
  темы `focus_ring`/`sel_border` (красные акценты больше не могут утекать в
  фокус).
- `os.system()` → `subprocess` для пересборки моста / открытия каталога логов.
- Дублирующийся stub SPD «Enable ADB», неверное гейтирование экспериментального
  `fastboot_unlock`, мёртвый путь FUS→AP-slot и отсутствующий emit `finished`
  исправлены. Удалена мёртвая поверхность экспериментов LAB/Knox/QCN/PAC.

### Реструктуризация
- `python/core/frp.py` (god-файл) → `python/core/core.py` (реестр + потоки);
  `frp.py` теперь только FRP. Удалён мёртвый split `python/core/flows/`.
- Имена задач verb-first (`Remove FRP`, `Flash Firmware`, …); один канонический
  snake_case ключ на поток; нормализация регистра display-name.

### Документация
- Свежие скриншоты (`docs/samsung.png`, `mtk.png`, `spd.png`), переписанные
  highlights/matrix/layout README, архитектура CONTRIBUTING + правила потоков,
  этот changelog.

### boot.img + AVB (единый нативный движок)
- Новый движок операций над образами в мосте Rust (`src/imgtools.rs`): разбор
  заголовка Android boot, скан cpio newc, проп-патчинг (pad-in-place или
  magiskboot-style рост с перезаписью заголовка), детерминированный gzip
  (mtime=0, level 9), флаги AVB vbmeta. CLI `boot-info` / `boot-patch-adb` /
  `vbmeta-patch`.
- Python `spd_adb` репаковка + `core._patch_vbmeta_flags` делегируют с локальным
  откатом (сигнатуры и возвращаемые контракты неизменны).
- Работа по эквивалентности исправила два реальных бага: splice роста
  расходился с выравниванием читателя на 2 байта (повреждал каждую следующую
  запись — в обеих реализациях), и повторный патч рос на `\n` при каждом запуске
  (обе стороны теперь идемпотентны). Байты gzip намеренно исключены из паритета
  (реализации zlib различаются); совпадают декомпрессированное содержимое,
  размеры и поля.
- 6 юнит-тестов Rust + 9 cross-implementation тестов.

### PAC (единый нативный движок + запущенные GUI-действия)
- Новый движок SPD PAC в мосте Rust (`src/pac.rs`): parse/extract/pack с
  раскладкой YGDP, общие сборщики header/slot теперь также используются записью
  `spd-readback` (байт-идентичный вывод; её исторические doubled slot names
  карантинизированы, не распространяются). CLI `pac-parse` / `pac-extract` /
  `pac-pack`.
- Python `pac.*` делегирует с локальным откатом; новые `flow_pac_extract` /
  `flow_pac_pack` (только файлы, входы ofp-style env) зарегистрированы в FLOWS
  и сопоставлены в диспетчере GUI — ранее мёртвые кнопки PAC теперь работают.
- Тесты эквивалентности поймали и исправили реальный баг: локальный packer
  молча терял строку product (запись slice-copy); плюс защита от переполнения u32
  с идентичными сообщениями в обеих движках.
- 5 юнит-тестов Rust + 7 cross-implementation тестов (roundtrips в обе стороны,
  sanitize parity вкл. коллизии директорий, отображение ошибок).

### PIT (единый нативный движок)
- Новый движок Samsung PIT в мосте Rust (`src/pit.rs`): parse (раскладка
  28/132), строки header/model, нормализация имён, find, скан перекрытий,
  форензическая валидация + вердикты здоровья — байт-идентичные сообщения,
  сводки и вердикты по сравнению с реализацией Python на реальных дампах и
  граничных случаях (включая Python-`repr` parity для мусорных имён).
- CLI `pit-parse` / `pit-health` / `pit-find` / `pit-overlaps` / `pit-model`;
  Python `pit.*` сырые байты делегируют с локальным откатом при отсутствии
  бинарника (контракты сохранены: ValueError/None/never-raise). Пути
  in-memory-объектов и хелперы отображения остаются локальными и быстрыми;
  общие правила закреплены 11 cross-implementation тестами эквивалентности.
- 8 юнит-тестов Rust (векторы раскладки, таблица нормализации, классификация
  meta overlap, формы сводок/human-size).

### ADB (нативный транспорт, без platform-tools)
- Новый нативный ADB-клиент в мосте Rust (`src/adb.rs`): USB-транспорт
  (255/66/1) с отключением kernel-драйвера, CNXN-рукопожатие, RSA-SHA256/SHA-1
  AUTH (переиспользует `~/.android/adbkey`, генерируется при отсутствии),
  сервисы `shell:` и `sync:` (STAT/RECV/SEND).
- `adb-devices` сохраняет контракт строк `adb devices -l` из нативного скана
  (`device` / `unauthorized` / `no permissions`); `adb-shell` принимает serial
  (`-` = первый авторизованный), плюс новые закреплённые по serial
  `adb-pull` / `adb-push`.
- Python: `bridge.adb_shell()` разрешает явный > область видимости окружения >
  первый авторизованный serial (multi-device ADB теперь закреплён по цели);
  `adb.py` делегирует в мост; EFS backup/restore pull/push идут через мост
  вместо незакреплённых системных вызовов `adb`. `has_adb()` теперь означает
  «мост собран».
- 6 тестов Rust (фрейминг, banner, PKCS#1 sign/verify, DER roundtrip,
  бит-идентичный pubkey blob по сравнению с ключом системного adb) + 9 тестов
  Python.

### Fastboot (нативный транспорт + Motorola universal)
- Новый нативный fastboot USB-транспорт в мосте Rust (`src/fastboot.rs`):
  `fastboot-devices` (JSON) + `fastboot-cmd <vid:pid@bus:addr> <ms> <cmd…>`
  для фазы команд (getvar/oem/erase/reboot) с отключением kernel-драйвера.
  FAIL со стороны устройства отображается как `FAILED (remote: …)` с выходом 0,
  согласно форме транскрипта системного бинарника (включая одиночные значения
  `getvar`, которые едут в OKAY-пакете на загрузчиках Moto MBM).
- Общие хелперы Python (`_fastboot_run`, `_wait_fastboot`, `_fastboot_getvar`)
  нативно-приоритетны с откатом к системному бинарнику; команды фазы DATA
  (flash/boot/…) всегда используют системный бинарник, а хостовый список
  `devices` отдаётся из нативного detect. Весь трафик fastboot теперь
  закреплён по цели (`vid:pid@bus:addr`), закрывая опасность «без `-s` — не
  тот телефон».
- Новые потоки уровня бренда Motorola (`moto_frp_adb`, `moto_frp_fastboot`,
  `moto_oem_unlock_token`): сброс через ADB provisioning, официальный поток
  unlock-token с чтением состояния блокировки + сброс сессий, читатель токена
  только для чтения. Показываются в Motorola → All Motorola / Lenovo
  (universal) и каждой модели Moto; исправлен URL портала разблокировки (старый
  `motorola.com/unlockbootloader` мёртв).
- `python/core/fastboot.py` (Pixel) и `usb_watch.py` (lsusb scraping) переведены
  на мост; 7 новых тестов `tests/test_fastboot_native.py`.
